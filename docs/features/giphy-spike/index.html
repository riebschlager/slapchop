What this can and cannot tell you

  • fetch() only exposes CORS-safelisted headers plus those the server names in Access-Control-Expose-Headers. Record full headers from the curl commands in the report, or the devtools Network tab — not from this page alone.
  • A failed fetch surfaces an opaque TypeError. A CORS rejection, a DNS failure, and an offline network are indistinguishable from script. Confirm in devtools before recording a verdict.
  • A plain <img> needs no CORS grant. Previews loading proves nothing about whether the importer's fetch of the original rendition will work.
  • Retry-After can only be observed on an actual 429. Leave burst at 0 unless you are deliberately spending quota to observe rate limiting.
